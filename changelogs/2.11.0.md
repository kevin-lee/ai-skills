## New Feature

### Track skill versions so `update` skips unchanged skills (#166)

#### Before This Release

`update` replaced every installed skill that had source metadata on every run. It had no way to know whether the source had changed, so skills that were already current were rewritten each time, and the output could not tell which skills actually changed. Any edits made to an installed skill were silently overwritten by the next `update`.

#### After This Release

`.aiskills.json` now records a version for each skill, and `update` compares it with the source before touching anything. Every skill gets one result line with a distinct status.

```
✅ Updated:       2020-hindsight-scala (global, Claude): ~/.claude/skills (1a2b3c4 → 5d6e7f8)
🟩 Up to date:    pr-analysis (global, Claude): ~/.claude/skills
🟨 Local changes: riper-5 (global, Claude): ~/.claude/skills (source unchanged)
🟨 Local changes: archify (global, Claude): ~/.claude/skills (source updated - use --force to overwrite)
🟥 Skipped:       foo (global, Claude): ~/.claude/skills (git clone failed)

Summary: 1 updated, 1 up to date, 2 local changes, 1 skipped (5 total)
Local changes (2): riper-5, archify
Run `aiskills update --force <skill-name>` to overwrite local changes.
```

* **Updated**: the source folder changed, so the skill was replaced. The line shows the short version change.
* **Up to date**: the source folder is unchanged, so the skill's files are left untouched.
* **Local changes**: the installed files were edited after installation, and they are kept. If the source also changed, `--force` is needed to overwrite them.
* **Skipped**: the skill could not be checked, for example because the clone failed or it has no source metadata.

**Versions**

* A skill's version is the Git tree hash of its own folder, not the repository commit. A commit that only changes other paths in the same repository does not make a skill out of date.
* Git sources use `git rev-parse HEAD:<subpath>`. Local sources get the same value from a temporary index and `git write-tree`, so versions are computed with Git for both.
* Hashes leave out `.aiskills.json`, `.DS_Store`, `Thumbs.db` and `desktop.ini`, and normalize line endings.
* A hash of the installed copy is recorded as well. It changes only when `aiskills` writes the skill's files (install, marketplace install from `search`, the rename flows, `update` and `sync` rename), so a mismatch means the files were edited locally.

**`--force`**

`update` accepts `--force` (`-f`) to update regardless of the recorded versions.

```bash
aiskills update --force commit
```

A forced update of unchanged content shows `(forced)` instead of a version change.

**Metadata**

`.aiskills.json` gains four optional fields:

* `commit`: the Git commit the installed content came from (Git sources only, for display)
* `sourceHash`: the Git tree hash of the source skill folder
* `installedHash`: the Git tree hash of the installed files
* `checkedAt`: when `update` last checked the skill

`checkedAt` is written for global skills only. `sync` drops it from project copies, so a project that commits its skills does not get a diff on every run.

`read` shows the new fields:

```
          commit: 3f9c2a1d8e7b6c5a4f3e2d1c0b9a8f7e6d5c4b3a
      sourceHash: 5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e
       checkedAt: 2026-09-27T01:23:45.678Z
```

**Notes**

* Skills installed by 2.10.0 or earlier have no recorded version. Their next `update` replaces them as before and records one, so no migration is needed.
* When a missing branch is switched to the default branch (#162) and the content there is identical, the files are kept and the switch is still recorded, so the prompt is not shown again.
* A skill whose version cannot be recorded is updated on every run, as before, and listed in the summary:
  ```
  Versions not recorded (1): my-skill
  A version cannot be recorded without Git or when the source folder contains a symbolic link. These skills are updated on every run.
  ```
  This happens when Git is not available, or when the source folder contains a symbolic link, because the link may point outside the folder.
* Scala Native has no `java.security.MessageDigest`, which is why Git's own tree hash is used instead of a hand-rolled digest.

## Bug Fixed

### Fixed: Installing or updating a repo-root skill copied the clone's `.git` directory into the installed skill (#167)

#### Before This Release

When a skill's `SKILL.md` was at the root of its Git repository, `install`, `update` and marketplace installs from `search` copied the whole temporary clone into the installed skill directory, including `.git`. Local-source installs and `sync` also copied any `.git` found in the skill folder.

* The installed skill became a Git repository of its own and carried the source repository's objects and refs.
* In a project that commits its skills (e.g. `.claude/skills/`), Git treated the installed skill as an embedded repository and recorded it as a gitlink (mode `160000`) instead of its files, so anyone who cloned the project got an empty skill directory.
  ```
  warning: adding embedded git repository: .claude/skills/root-skill
  ```
* `update` put `.git` back every time it replaced the skill, even after it had been removed by hand.
* `sync` spread a copied `.git` to the other agents' skill directories.

Skills in a subfolder of a repository were not affected through Git sources, because the subfolder has no `.git`.

#### After This Release

Every skill folder copy in `install`, `update` (Git and local-source), `search` and `sync`, including the rename flows, now leaves out every entry named `.git` at any depth, whether it is a directory or a file. The size shown in the `install` selection list skips `.git` too, so it matches what is copied.

```
$ ls -a .claude/skills/root-skill
.  ..  .aiskills.json  SKILL.md
```

Skills installed by 2.10.0 or earlier have no recorded version (#166), so their first `update` after upgrading replaces them with a copy without `.git`. Recorded versions are unaffected, because the version hash already ignores `.git`.
